How it works

  1. Author a course as config.json — screens, questions, branches, scoring, theme, and certificate in one file.
  2. Validate it against the JSON Schema. Bad configs fail loudly at build time with exact paths — never silently in front of a learner.
  3. Render it with the engine: semantic HTML, focus management, live-region feedback, and required alt text on all media.
  4. Ship it as a SCORM 1.2 package (node build.js --course <name>) or as a plain web page like this one.

Under the hood

Hand-rolled validator

Cross-reference checks, unreachable-screen detection, and alt-text enforcement run identically in the player and the build script.

4KB state budget

SCORM 1.2 suspend-data holds deltas only — screen IDs and scores, never content. Demo payloads measured under 700 bytes.

Real LMS proof

Both courses passed SCORM Cloud testing: completion, success status, and score all reported correctly, including resume-after-relaunch.
